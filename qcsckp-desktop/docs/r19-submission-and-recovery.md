# v0.1.66 r19 本机修复与验收

基线为 r18 / `b6b058233bd0542d922bb51e64fe88cd94688503`。本轮仅本机使用，不生成 ZIP、不推送 GitHub 或服务器。

## 六项修复

1. **提交结果不可降级**：HTTP发送闸门位于限流和Token准备之后。共享意图记录 `not_sent/sending/accepted/unknown/rejected`；已接受或未知时，审计、入队及线程异常只进入只读对账，不转为可重试的明确失败。发送中的历史意图重启后只做GET核验。
2. **领取权真正生效**：领取递增fence，回报/心跳/提交闸门核验原账号、父卡、token、fence和有效期。旧worker失权后不再提交；已经发送的原意图不因卡片过期重新排队。核验终态可凭原领取证据接管过期卡，但不会抢走仍有效的多组父卡，也不恢复POST权限。
3. **首次投递可靠恢复**：任务和每个接收人的outbox同事务保存。稳定UUID、正文、收件人、用途和首次尝试时钟冻结；同UUID仅在原TTL及50分钟内重试，最多8次。回执原子合并；旧无投递证据的卡不盲目补发。确认卡等待长连接就绪，不消耗发送次数；终态通知不依赖长连接。
4. **指标真实读取时间**：素材按相关请求较早起点计算年龄；调控使用独立 `metrics_observed_at`，状态更新时间不再充当指标时间。旧NULL等待新采。热采不再同步阻塞等待昨日补采。
5. **按计划唤醒**：提交采集快照后只请求对应计划复核，1秒合并，扫描期间新事件不会被清掉。保留300秒全量兜底和已批准停投任务的独立短轮询。
6. **历史缺口修补**：按对象限制日志在途请求；失败长窗口拆为30分钟修补片，成功区间先合并再求必需对象交集。D+1 02:00、D+2 06:00有界校准，离线恢复合并到期阶段；允许显式刷新成功窗口，失败复核保留旧可信数据。历史素材使用独立低优先级job，逐GET借还账户槽位，不占整段降级锁，不更新latest或触发实时规则。

## 数据与接口

- 只增量增加两列：`pmc_roi2_assist_task.metrics_observed_at TEXT NULL`、`operation_log_sync_window.last_success_at TEXT NULL`。不新增表。
- 原日志成功/空窗口可从完成时间回填 `last_success_at`；失败记录不回填。新读取以成功批次请求起点记录时间，不能用晚完成时间冒充后续校准阶段。
- `request_*_rule_evaluation(..., target_uids=None)` 中 `None` 表示全量，空集合不触发扫描。
- 首次创建返回 `delivery_state / queued_count / sent_count`；“已入队”不再被记录为“已送达”。
- outbox新协议复用既有列，冻结信息放在JSON中；旧孤儿卡保留原去重键和TTL，显示投递待核实。
- UUID去重参考[飞书官方SDK消息请求模型](https://github.com/larksuite/oapi-sdk-go/blob/v3_main/service/im/v1/model.go#L12759)。该保证不代表一定能重新取得原消息ID；无回执仍按未知处理。
