# 采集数据不更新/不完整修复记录

本文档对应 2026-08-19 《cc修复千川.txt》的开发落地。修复前回滚点：`v0.1.52-pre-collection-completeness-fix`。

## 已落地

- 新监控计划用5秒探测种子，10账户×10计划首轮全部准入。
- 耗时变慢立即收紧，变快按 EWMA 恢复；容量等待目标每轮限量重测。
- 非429失败不再阻止全局并发恢复；只有多个账户短时同时429才升级应用级退避。
- 手动刷新不再清除正在执行任务的租约，高优先级重新刷新不会丢失。
- owner 解析统一为 `local_default` 安全回退，快照、队列、退避和账户使用同一口径。
- 商品计划恢复展现、点击、点击率和转化率官方指标。
- 缺失指标保存为 `NULL`，不再用0覆盖上轮真值；无可用指标时本轮安全失败。
- 素材分页改为串行，分页证据缺失/页大小不一致时拒绝覆盖旧数据。
- 暂停/消失素材改为 `paused/removed` 软标记，保留消耗；7天后才清理 removed 最新行。
- 追投任务响应缺少 `scene` 时放行，仅显式冲突时拒绝。
- 历史维护永远校验 compact 替代数据存在后才删除旧行。
- 飞书多维表新增/更新按500条分片，任一分片失败都会抛错，不再假成功推进水位。
- 操作日志30天补录改为24小时分段推进，调度异常记录完整日志。
- 跨日重启时单独回补昨日最终素材指标，不污染今日规则数据。
- 后台运行主管每30秒检查并重启关键工作器。
- SQLite 并发 upsert 串行保护，`insert_many` 使用全部行的列并集。
- 小时快照保留180天，防止无限增长。
- PHP 备份接口拒绝无效/截断 JSON，修复唯一键、upsert、坏行返回和最新200点排序。

## 保留的安全边界

- 同一千川账户的计划默认仍串行；未经真实配额压测前不盲目放开账户内并发。
- POST 写操作仍不盲目重试，结果不确定时只做任务列表/操作日志对账。
- `browser_legacy` 只作 Git 回滚通道，不作官方 API 运行时自动降级。
