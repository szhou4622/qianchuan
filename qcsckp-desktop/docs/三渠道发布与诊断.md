# QCSCKP 三渠道发布与诊断

## 边界

- Windows x64；业务基线为 v0.1.65 / c1f4443。正式与开发初次发布 v0.1.66 r1，稳定 v0.1.65 r1。
- 保留同一个授权 app_name=QCSCKP、机器标识和 DPAPI 凭证；不改线上授权数据库。
- 开发版只是私下分发，不是访问白名单。任何有效 QCSCKP 激活码取得开发包后都能使用。
- 稳定包仅回补渠道、授权共享、切版保护和诊断基础设施，原始 0.1.65 ZIP 永不覆盖。
- 开发时原仓库已有一组未提交的授权网络诊断/安全 HTTPS 修复；已复制到独立工作树保留。原仓库未修改。

## 本机布局与恢复

`%LOCALAPPDATA%\QCSCKP\channels\{production,development,stable}` 各有独立 data、logs、temp。
`shared-v1\identity` 保存统一的 DPAPI 凭证；`shared-v1\execution.sqlite3` 仅共享执行对账、不可变幂等键和两张成功限频表。
原 `official-api-v1` 数据只读复制并保留。切版先一致性备份，再关闭策略并废止待确认指令；旧业务数据不反向覆盖或合并。
“版本与诊断”按钮只读核验平台计划和调控任务；存在未知提交则继续阻止写入，需等待原执行对账或人工查明结果。核验不会创建或关闭任何投放任务。

同渠道更新以 `.qcsckp-update` 中的独立暂存区校验 ZIP、渠道及关键文件，等待旧进程正常退出。替换发生异常时恢复原文件；更新成功也保留 previous-version。不要将新数据库直接交给旧原始 EXE 使用。

## 构建和发布

构建脚本必须明确 Version/Channel，PythonPath 可指向已有 Python 3.12 虚拟环境：

```powershell
./packaging/windows/build_windows.ps1 -Version 0.1.66 -Channel development -BuildRevision 1 -PythonPath '<Python 3.12 虚拟环境路径>'
./scripts/publish-qcsckp-update.ps1 -Version 0.1.66 -Channel development -BuildRevision 1 -ZipPath '<已验收ZIP>' -NotesFile docs/channel-release-notes.md
```

发布前提交源码，安装包 source_commit 与发布清单必须一致。构建目录存在时拒绝覆盖。
渠道下载路径为 `/downloads/QCSCKP/<channel>/<version>/r<revision>/<包名>`。
更新接口 `/api/update/latest?app_name=QCSCKP&channel=<channel>`；旧客户端不传 channel 时仍是 production。
development/stable 发布不会修改 production；稳定清单首次发布后冻结。

## 服务端部署与查询

`server/deploy_services.sh` 仅在 `/tmp/qcsckp-channel-server-*` 暂存目录运行。它校验现有文件的预期 SHA，拒绝覆盖并发变更，保存配置备份，失败自动回退。8797 是新诊断服务的 loopback 端口；8796 属于另一应用，不使用。
诊断 POST `/api/qcsckp/diagnostics` 使用现有设备会话验证 QCSCKP 身份，不接受其他产品、不保存凭证。
事件白名单、单条64KB、每设备10条/分钟、事件ID去重；本机最多1000条、7天，服务端30天。未知/过期授权和断网时延迟上传，可手动导出。

```sh
python3 /opt/qcsckp-diagnostics/diagnostics_server.py --query --diagnostic-id '<用户显示的诊断编号>' --hours 24
systemctl status qcsckp-diagnostics ovdt-update --no-pager
```

授权网络对照日志 `/var/log/nginx/qcsckp-support.log` 仅记录路径、渠道、request_id、状态和耗时，不包含查询参数、正文或授权头。
停用诊断服务不影响授权或更新；回退更新入口应恢复 production 渠道清单和兼容的 QCSCKP/latest.json 两份指针，不覆盖或删除已发布 ZIP。

## 验收

- `python -m unittest discover -s tests -q`；所有数据测试使用独立 QCSCKP_HOME，投放接口使用模拟对象。
- 三渠道首次复制、切回隔离、DPAPI 凭证保留、互斥锁、共享幂等与限频、未知结果阻止重提。
- 正式/开发清单不串线，稳定不升级；ZIP 越界路径、身份不一致、篡改关键文件均拒绝。
- 原生 PowerShell 安装器注入移动失败后恢复原程序；不强杀进程。
- 诊断消息含模拟密钥时不进入上报，离线保留、恢复补传、限流、去重和过期清理。
- 三个真实打包 EXE 使用空白测试目录启动检查，不使用真实广告账户或客户授权。
