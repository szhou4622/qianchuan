# 飞书确认追投接入说明

## 默认方式：桌面端本地长连接

测试1版默认由桌面工具通过 `lark-oapi 1.7.1` 建立飞书 WebSocket 长连接，直接接收绑定消息和卡片按钮。普通用户不需要服务器、域名、公网 IP、Cloudflare、Verification Token、Encrypt Key 或回调 URL。

用户登录工具账号后进入“飞书绑定”，只填写 App ID 和 App Secret。App Secret 按工具账号隔离，使用 Windows DPAPI 加密保存在本机，不上传中心服务器，也不写入日志或操作流水。

飞书应用需开通以下权限：

```json
{
  "scopes": {
    "tenant": [
      "im:message:send_as_bot",
      "im:message:update",
      "im:message.p2p_msg:readonly",
      "im:message.group_at_msg:readonly"
    ]
  }
}
```

在“事件与回调”选择“使用长连接接收回调”，订阅 `card.action.trigger` 和 `im.message.receive_v1`，发布应用后再用页面生成的10分钟绑定码完成个人和群绑定。

追投任务、卡片消息 ID、点击状态和参数快照保存在桌面端 SQLite。工具必须保持运行才能接收按钮。工具关闭期间点击不会执行；重新启动并显示“已连接”后，需要在30分钟卡片有效期内重新点击。

## 兼容方式：旧 PHP 公网回调

以下内容仅用于兼容测试。普通用户设置中不再展示此模式。

旧模式由云端 PHP 接口负责发送和更新飞书卡片，桌面端保存可撤销设备令牌，并在用户确认后领取任务、复核规则和执行追投。

### 1. 配置服务端

将 `config.example.php` 的 `feishu_app` 段复制到实际 `config.php`，填写：

- `app_id`、`app_secret`：飞书自建应用凭据。
- `verification_token`、`encrypt_key`：卡片回调校验参数。
- `authorized_open_id`：唯一有权确认或拒绝追投的人。
- `chat_ids`：接收提醒的群 ID 列表。
- `open_ids`：接收提醒的个人 Open ID 列表。

群和个人可以只启用一种，也可以同时启用。所有真实凭据只能放在服务器的 `config.php`，不要提交到仓库，也不要放入桌面端配置。

服务器需启用 PDO MySQL、cURL、OpenSSL 和 mbstring。正式发布建议先备份数据库，再执行
`doc/schema_feishu_retarget.sql`；运行时仍会幂等检查设备令牌、追投任务、卡片消息和卡片更新队列表。

为让按钮回调快速返回、群卡与个人卡在后台同步，并让桌面端长期离线时卡片准时显示“已过期”，
在服务器计划任务中至少每分钟执行一次（支持秒级计划任务时建议每 5～10 秒）：

```
php /你的部署目录/cron/expire_retarget_tasks.php
```

该脚本只能从命令行运行，不能通过网页访问。

### 2. 配置飞书应用

在飞书开放平台启用机器人以及发送、更新消息所需权限，并把交互卡片回调地址设置为：

```
https://你的域名/api/feishu/card_callback.php
```

回调必须是公网 HTTPS。完成 URL 校验并发布应用后，将机器人加入目标群，或确保应用能够向目标个人发消息。

飞书官方接入参考：[事件驱动消息与消息卡片](https://open.feishu.cn/document/home/event-based-messaging/message-card-reference)；上线前应在飞书 API 调试台用当前租户验证一次发送、点击回调和编辑消息。

### 3. 桌面端启用

用户在桌面工具重新登录后，云端会签发 90 天设备令牌。令牌只保存在本机 `data/device_session.json`，同一账号和设备再次登录时会撤销旧令牌。

在“规则追投”中把策略执行方式设为“飞书确认后追投”。旧策略会自动迁移到这个安全默认值；明确选择“自动追投”的策略继续走原有自动执行流程。

## 本地长连接验收顺序

1. 在没有公网服务器和 Cloudflare 的情况下确认页面显示“已连接”。
2. 生成个人绑定码并完成绑定，再发送测试卡片。
3. 用测试素材和受控预算命中一条规则，确认群或个人只收到一张有效卡片。
4. 用非授权账号点击，确认被拒绝；再由授权 Open ID 点击“确认追投”。
5. 确认桌面端重新检查登录态、账户、素材最新数据、策略版本和限频后才执行。
6. 确认成功卡片包含千川调控任务 ID，且“账户操作流水”只有一条有效追投记录。
7. 同时发送群卡片和个人卡片时，从任一端处理后，另一端也应同步为终态。

真实追投验收前，先用模拟飞书回调和模拟千川响应完成接口测试。

## 5. 账户操作流水

“账户操作流水”页面必须先选择一个 `aavid`，默认显示最近 7 天。点击“打开千川并记录操作”后，工具会记录浏览器中的写操作，并发现千川后台操作日志接口；发现后每 5 分钟增量同步。

页面显示的“覆盖时间”是实际已读取的后台日志范围。如果接口、页面或权限发生变化，会显示“外部流水同步异常”，不会把不完整的外部流水标记为完整。工具自身追投和停投记录不受影响，统一流水按 180 天保留。
